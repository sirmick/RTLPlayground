3. A pasted 500-character line
-----------------------------------------------------------------------------

Script: /tmp/f1r/paste.py. 500 printable characters and Enter, in one UART
write.

At an idle prompt, on NEW (both boards):
- The echo is exactly the first 127 characters (the editor's CMD_BUF_SIZE
  - 1).
- The line runs ("Error: Unknown command").
- con rx overruns 0, and the console answers after it.
- That is intact as testing.md and D1 define it (d1-uart-rings.txt). OLD
  behaves the same, minus the overrun count.

During a running command, typed 50 ms or 2 s into a 3.2 s `l2` of 1000
entries:
- NEW echoes the first 127 characters but loses the line's Enter.
- con rx overruns 246 = 501 - 255. The 256 B RX ring holds what arrives while
  the command runs, and the rest is lost.
- This is the design: con reads no more until cli has taken the line, and
  con_line_ready is cleared only in CLI_PROMPT (console.md, "As built (D3)").
  So type-ahead during a command is bounded by the RX ring.
- OLD loses the whole paste (no echo at all).
- Not a step-length issue: no step exceeds 3.6 ms there.
- If type-ahead longer than 255 B during a long command should survive, con
  would have to keep draining into the editor while cli runs. That is a
  design change (U2), not an F1 fix.
