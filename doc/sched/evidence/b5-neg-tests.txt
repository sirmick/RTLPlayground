## The watchdog timing (why hang reads 4995..4999 ms, not 5000)

The software watchdog counts timer ticks (5 ms, SWDT_TICKS 1000) from the
pass's kick, not from the step's start. sched_pass kicks it once a pass, and
SL_HANG starts later in the same pass, so the reset comes at the 1000th tick
after the kick: (c-1)*5 < t <= c*5 ms after SL_HANG starts, where c is the
count when it starts (c = 1000 when it starts in the kick's tick, 999 one
tick later). The test reads swdt_cnt at SL_HANG's entry, asserts c is 999 or
1000 and the reset falls in that window, the record's age == c, and the boot
line prints 5*age ms. Here c = 1000 both times: 4995.132 and 4999.258 ms.
