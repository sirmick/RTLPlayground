## A 500-character paste (rtlsim, normal firmware)
500 printable characters + CR in one uart write, then 1 s:
  con_rx_overruns 0; the echo is exactly the first 127 characters (the
  editor's CMD_BUF_SIZE - 1); the line runs (Unknown command).
Found on the way, not D1's (the editor is unchanged): 40 x "ip\r" pasted at
once run 2; the rest echo mangled. cmd_edit copies a printable character into
cmd_buffer before it checks cmd_available, so typing while a command is
pending writes over it. Before D1 the 16 B ring lost those bytes instead.
That is U4's shared buffer (M2/D3).

## Old vs new (ovs-rtlpg bb0ee65 tests/oldnew, rtlsim bb0ee65; OLD = fork main b635486, ~/src/rtlpg-ref)
NEW = a35bac2, built clean in a worktree (tools/docker-make.sh MACHINE=... LAYOUT=compact LOADER=1).
From ~/src/ovs-rtlpg:
  python3 tests/oldnew/oldnew.py --old <b635486 -boot> --new <a35bac2 -boot> --board boards/<board>.json [--expect d1-oldnew.expect]
| board | without --expect | with d1-oldnew.expect |
|---|---|---|
| 8x (keeplink_kp_9000_9xhpml_v1_2) | 10 of 13 match | 13 of 13 match |
| SWGT024 (swgt024_v2_0_unmanaged) | 11 of 13 match | 13 of 13 match |
13 scenarios: boot cli web vlan stp lacp lacp_slow loop igmp config upload sfp
flaps. bb0ee65 compares the console between steps ("<n> console"), learns MACs
on nic inject (a real l2 table), has the LACP partner (lacp, lacp_slow) and
counts frames; none of those shows a D1 difference. `upload reg 06f4` is the
8x's only (on SWGT024 its expect line matches nothing; the harness flags it,
without failing).
Every difference, explained (doc/sched/evidence/d1-oldnew.expect lists them, each
as narrow as the harness's names allow): write_char no longer waits ~87 us a
byte on the wire, so the code after a print runs before its bytes are out and
the firmware is a little ahead of the old at the scenarios' fixed times.
- `stp 002 cli stp status`, `005 /stp.json`, `006 /stpcnt.json`: STP runs that
  much sooner: tx counts +1, ages 40/0 for 39/1, tcs 0x16 for 0x15
- `loop frames * rldp`: 99 RLDP probes per linked port for 98
- `upload reg 06f4` (SEC_COUNTER, 8x): the update's reset falls the other side of a second
(On 2f3b6dd, 12 scenarios, the 8x's `000 boot` differed too, the boot slot's
text ending a few characters further on; bb0ee65 reads the boot to the prompt,
so it matches.)
None of the reference scenarios pastes a line, so the 256 B ring's paste
behaviour (and U2's) isn't exercised here; tools/console_bugs.py does (D3
evidence). The drain before a reset is in upload's path ("Resetting to apply
update") and shows no difference.
