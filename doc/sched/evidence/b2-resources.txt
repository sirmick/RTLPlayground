# B2 evidence: the scheduler core linked into the 8x image (temporary link)
# 2026-11-18, feat/sched + B2 files, SDCC 4.6.0 (in-tree toolchain)

## How

Not wired into the firmware (that is M2). One build with:
- output/b2-probe.mk (below) adding sched.c, con_ring.c, crash.c (resident), sched_bank.c, sched_health.c (banked),
  and the golden tables of test/sched_gen/golden (modules.md's set: 38 states, RUN_SEQ_LEN 72)
  with an empty banked step per state (step names prefixed p_: stp_step and sfp_wake exist in the firmware);
- rtlplayground.c's ISRs patched as they will be in M2 (diff below), reverted after the build.

tools/docker-make.sh -f Makefile -f output/b2-probe.mk MACHINE=KEEPLINK_KP_9000_9XHPML_V1_2 LAYOUT=compact LOADER=1 BUILDDIR=output/b2-probe  -> exit 0
(check_linked.py and check_cross_bank.py ran in it and passed)

    PROBE = schedprobe
    B2_BANKED = $(BUILDDIR)/sched_bank.rel $(BUILDDIR)/sched_health.rel $(BUILDDIR)/$(PROBE)/sched_gen_names.rel $(BUILDDIR)/$(PROBE)/steps.rel
    B2_RESIDENT = $(BUILDDIR)/sched.rel $(BUILDDIR)/con_ring.rel $(BUILDDIR)/crash.rel $(BUILDDIR)/$(PROBE)/sched_gen.rel
    SRCS += sched.c sched_bank.c con_ring.c crash.c sched_health.c $(PROBE)/sched_gen.c $(PROBE)/sched_gen_names.c $(PROBE)/steps.c
    RESIDENT_SRCS += sched.c con_ring.c crash.c $(PROBE)/sched_gen.c
    CC_FLAGS += -I$(PROBE)
    $(B2_BANKED): BANK_FLAGS = $(BANKED_FLAGS)
    $(BUILDDIR)/placed.stamp: $(B2_BANKED) $(B2_RESIDENT)
    $(shell mkdir -p $(BUILDDIR)/$(PROBE))

Resident pieces (CSEG/CONST from the .rel files): sched.c 606, crash.c 266, con_ring.c 149,
sched_gen.c (tables) 172; the ISRs +134 (rtlplayground.rel CSEG 6589 -> 6723); start-up/HOME +42.
Banked: sched_bank.c 1633, sched_health.c 1514 (bank 1 and 3 here; place_banks.py puts
sched_health with sched_gen_names, which it reads).

First attempt, all of sched.c resident (2131 B): the common area overflowed 0x4000
("Bank 0: code segment too large"). Hence the split in core.md.
