# O1 evidence: a banked function's bank byte from a C __code initializer
# SDCC mcs51 TD- 4.6.0 #16555 (Linux), the in-tree toolchain (toolchain/sdcc-1397895099), 2026-11-18

## 1. What SDCC accepts (sdcc -mmcs51 -c, one file per variant)

Rejected, 'Initializer element is not a constant expression':
  (uint8_t)(uint16_t)f, (uint8_t)((uint16_t)f >> 8), (uint8_t)((uint32_t)f >> 16)   -- any cast of a function address
  __code const uint32_t t[] = { (uint32_t)f };
Rejected, 'incompatible types ... __banked ... to ... __code':
  a plain void (*)(void) table holding a __banked function
Accepted, 2 bytes only (no bank):
  (__code const void *)f                    -> .byte _f, (_f >> 8)
Accepted, 3 bytes WITH the bank byte:
  typedef void (*step_fn)(void) __banked;
  __code const step_fn t[] = { f };        -> .byte _f, (_f >> 8), (_f >> 16)

## 3. Through the real build (place_banks.py, check_linked.py, check_cross_bank.py all pass)

Probe, a resident file added for one build only (not committed):
  /* O1 probe (temporary, not committed): a banked function-pointer table in the common area */
  #include <stdint.h>
  void rldp_tick(void) __banked;
  void stp_timers(void) __banked;
  typedef void (*step_fn)(void) __banked;
  __code const step_fn o1_step_addr[3] = { 0, rldp_tick, stp_timers };
